# ДЕТАЛЬНЫЙ ПЛАН: Интеграция

## 📍 Текущая проблема

### 8.1 Синхронный FTP
**Файл:** app/integration/services/ftp_service.py

Используется ftplib (синхронный) в асинхронном приложении.

**Влияние:** Блокировка event loop, замедление всех запросов.

### 8.2 Синхронный DaData
**Файл:** app/infrastructure/external/dadata.py

Библиотека dadata синхронная.

**Влияние:** Блокировка event loop при нормализации адресов.

### 8.3 Нет обработки повторного импорта
**Файл:** app/integration/services/integration_service.py

Один и тот же файл можно импортировать несколько раз.

**Влияние:** Дубликаты данных.

### 8.4 Нет TLS для FTP
**Файл:** app/integration/services/ftp_service.py

FTP без шифрования.

**Влияние:** Перехват данных, утечка паролей.

### 8.5 Нет обработки ошибок парсинга
**Файл:** app/integration/adapters/zln_adapter.py

Парсер падает на некорректном XML.

**Влияние:** Остановка импорта при плохом файле.

## 💡 Варианты решения

### Вариант A: Асинхронные клиенты
Перевести FTP и DaData на асинхронные библиотеки
- **Плюсы:** Правильная архитектура
- **Минусы:** Нужно найти подходящие библиотеки
- **Сложность:** Средняя (1 день)
- **Влияние:** Высокое

### Вариант B: ThreadPoolExecutor
Запускать синхронные операции в отдельных потоках
- **Плюсы:** Минимальные изменения
- **Минусы:** Не масштабируется
- **Сложность:** Низкая (2 часа)
- **Влияние:** Среднее

### Вариант C: Полная переработка
Асинхронные клиенты + обработка всех ошибок + повторный импорт
- **Плюсы:** Надежная интеграция
- **Минусы:** Долго (3 дня)
- **Сложность:** Высокая
- **Влияние:** Высокое

## 🔧 Рекомендуемое решение

**Вариант B** для быстрого фикса + **Вариант A** для долгосрочного решения.
