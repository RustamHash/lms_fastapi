# ДЕТАЛЬНЫЙ ПЛАН: API качество

## 📍 Текущая проблема

### 5.1 Непоследовательный стиль
**Файл:** Все роуты

Где-то используются сервисы, где-то прямые SQL-запросы в роутах.

**Влияние:** Сложность поддержки, дублирование логики.

### 5.2 Импорты внутри функций
**Файл:** app/api/v1/parties/routes.py, app/api/v1/documents/routes.py

from app.parties.models import Address внутри функций.

**Влияние:** Сложнее читать код, возможны циклические импорты.

### 5.3 Нет обработки ошибок
**Файл:** Все роуты

Нет exception handlers для стандартных ошибок (IntegrityError, ValidationError).

**Влияние:** 500 ошибки вместо понятных сообщений.

### 5.4 Нет валидации бизнес-правил
**Файл:** Сервисы

Многие правила не проверяются (например, что документ принадлежит тому же депозитору).

**Влияние:** Несогласованные данные.

## 💡 Варианты решения

### Вариант A: Рефакторинг стиля
Привести все роуты к единому стилю с сервисами
- **Плюсы:** Чистый код
- **Минусы:** Много изменений (1 день)
- **Сложность:** Средняя
- **Влияние:** Среднее

### Вариант B: Только обработка ошибок
Добавить exception handlers
- **Плюсы:** Быстро (2 часа)
- **Минусы:** Стиль останется непоследовательным
- **Сложность:** Низкая
- **Влияние:** Среднее

### Вариант C: Полный рефакторинг
Стиль + обработка ошибок + валидация
- **Плюсы:** Профессиональный API
- **Минусы:** Долго (2 дня)
- **Сложность:** Высокая
- **Влияние:** Высокое

## 🔧 Рекомендуемое решение

**Вариант A** — начать с рефакторинга стиля, затем добавить обработку ошибок.

## 📝 Шаги реализации

## 🧪 Как проверить

Проверить обработку ошибок:
curl -X POST http://localhost:8000/api/v1/products -H "Content-Type: application/json" -d '{"depositor_id":1,"external_id":"dup","name":"Test"}' -H "Authorization: Bearer TOKEN"
# Должен вернуть 409 с понятным сообщением, а не 500

Проверить единый стиль:
grep -r "select(" app/api/v1/ | grep -v "services" | head
# Не должно быть прямых SQL в роутах
