# ДЕТАЛЬНЫЙ ПЛАН: Мониторинг и оптимизация

## 📍 Текущая проблема

### 9.1 Нет кэширования
**Файл:** Все приложение

Частые запросы к БД без кэша.

**Влияние:** Высокая нагрузка на БД, медленные ответы.

### 9.2 Нет метрик
**Файл:** Все приложение

Нет сбора метрик (Prometheus).

**Влияние:** Невозможно отслеживать производительность.

### 9.3 Нет алертов
**Файл:** Все приложение

Нет уведомлений о проблемах.

**Влияние:** Проблемы обнаруживаются после жалоб пользователей.

### 9.4 Логирование неструктурированное
**Файл:** app/infrastructure/logging/setup.py

Логи в текстовом формате, не JSON.

**Влияние:** Сложный анализ логов.

## 💡 Варианты решения

### Вариант A: Базовый мониторинг
Prometheus + Grafana + базовые метрики
- **Плюсы:** Стандартное решение
- **Минусы:** Нужна инфраструктура
- **Сложность:** Средняя (1 день)
- **Влияние:** Высокое

### Вариант B: Полный мониторинг
Метрики + алерты + structured logging + кэширование
- **Плюсы:** Полная картина
- **Минусы:** Сложно (3 дня)
- **Сложность:** Высокая
- **Влияние:** Высокое

### Вариант C: Минимальный старт
Только structured logging + базовое кэширование
- **Плюсы:** Быстро (полдня)
- **Минусы:** Нет метрик
- **Сложность:** Низкая
- **Влияние:** Среднее

## 🔧 Рекомендуемое решение

**Вариант C** для старта, затем перейти к Варианту A.

## 🧪 Как проверить

Проверить structured logging:
curl http://localhost:8000/api/v1/health | jq
# Логи должны быть в JSON формате

Проверить метрики:
curl http://localhost:8000/metrics | grep http_requests_total

Проверить кэш:
redis-cli KEYS "*"
# Должны быть ключи кэша

- JSON логи могут быть сложнее для чтения человеком
